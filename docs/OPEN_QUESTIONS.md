# 구현 전 확인할 사항

2026-09-02 사용자 답변으로 배포, 인증, 파일 검증, 오프라인, LLM 방향을 확정했다. 남은 질문은 사용 경험을 조정할 때만 확인한다.

## 확정된 사항

- 개인 서버 한 대에 self-hosting한다.
- 초기 앱 로그인은 만들지 않는다.
- CSV는 UTF-8과 BOM UTF-8만 지원한다. CP949 자동 감지는 하지 않는다.
- 오프라인 학습은 지원하지 않는다.
- LLM 공급자는 Groq다.
- `GROQ_API_KEY`는 서버 환경변수에만 저장한다.
- Groq 호출은 내장 `fetch`와 고정 endpoint를 사용하고 범용 공급자 계층은 만들지 않는다.
- Groq 모델은 `openai/gpt-oss-120b`를 사용한다.
- 완전히 빈 행은 건너뛴다. 단어 또는 뜻 한쪽이 비었거나 길이 제한을 넘은 행이 하나라도 있으면 업로드 전체를 취소하고 최대 20개 오류 행 번호를 반환한다.

## 배포 전에 필요한 정보

1. 개인 서버 OS가 Linux인지, Windows인지?
2. Docker와 Docker Compose를 사용할 수 있는지?
3. 모바일에서 접속할 도메인과 HTTPS가 이미 있는지?
4. 접속 범위가 집 안 LAN 전용인지, 외부에서도 접속해야 하는지?
5. 외부 접속이 필요하면 VPN/Tailscale과 리버스 프록시 인증 중 어느 방식을 선호하는지?

앱 로그인이 없으므로 4~5번은 실제 공개 전 반드시 확정한다.

## 파일 제한 질문

6. 보통 하루 단어 수와 가장 큰 예상 파일 크기는 어느 정도인지? 답변 전 기본 제한은 10 MiB, 5,000행이다.

## UX 정책 질문

7. 뜻을 눌러 본 뒤에는 10초 timer를 완전히 멈추는 것이 맞는지? 현재 계획은 멈춤이다.
8. 시간 초과 뒤 뜻을 보여주는 시간은 몇 초가 편한지? 기본안은 1.2초다.
9. 앱이 백그라운드로 가도 10초가 계속 흐르는 것이 맞는지? 현재 계획은 deadline이 계속 흐르며 복귀 즉시 timeout 처리한다.
10. Day 목록에서 과거 Day를 선택했을 때도 그 Day를 `N`으로 같은 누적 규칙을 적용하면 되는지? 현재 계획은 그렇다.
11. `전체 다시 반복하기`가 버튼을 누른 시점의 최신 데이터가 아니라 완료한 세션과 같은 카드 집합을 반복해야 하는지? 현재 기본안은 같은 target Day의 계획을 서버에서 새로 snapshot한다. Day 수정 기능이 없으므로 실질적으로 같다.
12. 예문 생성에 실패한 카드에 수동 `다시 생성` 버튼이 필요한지, 아니면 자동 재시도 후 `예문 없음`만 보여줘도 되는지?

## 알림과 오프라인 질문

13. 알림 시각은 하루 한 번만 필요하고 요일 선택은 없어도 되는지? 기본안은 매일 한 번이다.
14. 그날 업로드가 없어도 가장 최근 Day 기준으로 알림을 보내면 되는지? 기본안은 보낸다.
15. 여러 휴대폰/브라우저에 알림을 등록하면 모든 기기에 보내도 되는지? 기본안은 활성 구독 모두에 발송한다.

## 현재 기본값 요약

답변 전까지는 다음을 기준으로 구현 계획을 유지한다.

- 개인 서버 Docker Compose에서 web, worker, PostgreSQL 실행
- 로그인 없는 단일 owner
- Groq + `openai/gpt-oss-120b`
- UTF-8/BOM UTF-8 CSV, 첫 sheet, 첫 두 열, 10 MiB/5,000행
- reveal 순간 timer 정지, timeout reveal 1.2초, 백그라운드에서도 deadline 진행
- 과거 Day도 동일한 누적 규칙 적용
- `몰랐어요`와 시간 초과 카드는 그 라운드의 나머지 카드를 모두 본 뒤, 모르는 카드끼리만 다시 섞어 모두 `알았어요`가 될 때까지 반복
- 전체 카드 재시작은 모든 카드 통과 뒤 완료 화면의 `전체 다시 반복하기`에서만 실행
- 매일 한 번, 최신 Day 기준, 등록된 모든 기기에 알림
- 설치/푸시는 지원하지만 오프라인 학습은 지원하지 않음
