# 영어 단어 발음 듣기 상세 명세

- 연결 이슈: [#1 학습 카드에 영어 단어 발음 듣기 추가](https://github.com/chanbonggg/chanvoca/issues/1)
- 작성일: 2026-10-29
- 상태: 구현 및 자동 검증 완료 / 실제 기기 검증 대기
- 구현 범위: 프론트엔드 학습 카드

## 1. 목적

사용자가 단어의 뜻을 확인한 뒤 버튼을 눌러 해당 영어 단어의 발음을 듣는다. 기존 학습 흐름과 정답 기록을 유지하면서 듣기 기능을 추가한다.

1차 버전은 브라우저 Web Speech API의 음성 합성을 사용한다. 미국 영어 음성을 명시적으로 선택하고, 실제 사용 기기에서 발음 품질을 검증한다. 사전의 원어민 녹음과 같은 정확도를 보장하는 기능으로 안내하지 않는다.

## 2. 범위와 제외 사항

### 포함

- 수동으로 뜻을 확인한 학습 카드에 단어 발음 버튼 표시.
- 현재 카드의 영어 단어만 버튼 클릭으로 재생.
- 미국 영어 음성 선택, 초기 음성 목록 지연 처리.
- 반복 클릭 시 재시작, 카드 이동 및 화면 이탈 시 중단.
- 미지원 환경과 재생 실패에 대한 안내.
- 키보드 조작, 스크린 리더 안내 및 모바일 터치 영역.
- 기존 학습 동작의 회귀 검증.

### 제외

- 예문·한국어 뜻 재생, 자동 재생, 자동 반복.
- 음성·억양·속도 선택 설정 및 계정별 설정 저장.
- 발음 평가, 마이크 녹음, 음성 인식, 발음 기호 표시.
- 사전 음원, 외부 TTS API, 음성 파일 생성·저장·캐싱.
- 전체 단어 목록에서의 재생과 오프라인 재생 보장.
- 백엔드 API, DB 테이블·migration, worker 변경.

## 4. 화면과 조작 명세

### 4.1 표시 조건

정상 재생 버튼은 다음 조건을 모두 만족할 때 표시한다.

- 학습 상태가 `studying`이고 현재 카드가 존재한다.
- 사용자가 직접 뜻을 확인했다: `revealed === true` 및 `timedOut === false`.
- 정답 제출 중이 아니다: `saving === false`.

답 확인 전에는 숨기고 키보드 탐색 대상에도 포함하지 않는다. 시간 초과로 자동 공개된 카드는 1.2초 뒤 이동하므로 발음 기능을 제공하지 않는다. 이 예외는 기존 자동 제출을 지연시키지 않기 위한 것이다.

메뉴 또는 전체 단어 목록이 열려 있으면 배경 카드의 재생을 중단하고 버튼을 조작할 수 없게 한다.

### 4.2 배치와 문구

- 영어 단어 가까이에 스피커 아이콘과 `발음 듣기` 텍스트를 표시한다.
- 긴 단어에서는 버튼이 다음 줄로 내려가도 되며 가로 스크롤을 만들지 않는다.
- 접근 가능한 이름: `<현재 단어> 발음 듣기`.
- 재생 중에도 버튼은 활성 상태를 유지하고 `다시 듣기`로 표시한다. 다시 누르면 처음부터 재생한다.
- 재생이 끝나면 `발음 듣기`로 돌아온다.
- 기기에서 음성이 실제 출력됐다고 판단하는 상태는 `onstart`를 기준으로 한다. `speak()` 호출만으로 성공 처리하지 않는다.

### 4.3 접근성과 이벤트

- 실제 `button type="button"`을 사용하고 터치 영역은 최소 44×44 CSS px로 확보한다.
- Tab 이동, Enter·Space 실행, 눈에 보이는 포커스 표시를 지원한다.
- 발음 버튼의 클릭·키보드 입력은 상위 카드의 뜻 확인이나 정답 제출로 전파되지 않는다.
- 답 확인 후에는 카드 컨테이너의 `role="button"` 및 뜻 확인용 키보드 동작을 제거해 버튼 안에 버튼이 있는 접근성 구조를 피한다. 답 확인 전 카드 조작은 유지한다.
- 짧은 상태·오류 안내는 별도의 `role="status"` 영역으로 전달한다. 카드 전체를 반복 낭독하지 않도록 기존 `aria-live` 영역과 중복 안내를 확인한다.
- 발음 버튼을 누른 뒤 정답 버튼으로 계속 이동할 수 있다. 포커스를 강제로 옮기지 않는다.

## 5. 음성 재생 규칙

### 5.1 입력과 음성 선택

1. 재생 대상은 현재 카드의 `term`만 사용한다. 뜻과 예문을 붙이지 않는다.
2. 앞뒤 공백만 제거하고 원래 철자·대소문자·구두점을 보존한다. 비어 있으면 재생하지 않고 안내한다.
3. `SpeechSynthesisUtterance.lang`는 `en-US`로 지정한다.
4. `getVoices()`에서 언어 태그가 대소문자 무관하게 `en-US`인 음성을 선택한다. 제공자가 밑줄을 사용하면 하이픈으로 비교한다.
5. 동일 언어 음성이 여러 개면 브라우저 기본 음성을 우선하고, 없으면 목록의 첫 번째 음성을 사용한다. 특정 제조사의 음성 이름은 고정하지 않는다.
6. 선택한 음성을 `utterance.voice`에 명시적으로 지정한다. 한국어 기본 음성이나 다른 영어 억양으로 조용히 대체하지 않는다.
7. 속도·높이·볼륨은 플랫폼 기본값을 사용한다. 사용자가 바꾸는 설정은 만들지 않는다.

미국 영어 음성이 없으면 버튼을 비활성화하고 설치 안내를 표시한다. 음성이 있어도 정확한 발음이나 동일한 음색을 보장하지 않으며, 동형이의어의 문맥별 발음은 1차 범위에서 구분하지 않는다.

### 5.2 음성 목록 초기화

- 마운트 시 API 지원 여부를 확인하고 현재 음성 목록을 조회한다.
- `voiceschanged` 이벤트가 제공되면 구독해 목록을 갱신한다.
- 초기 목록이 비어 있다고 즉시 미지원으로 판정하지 않는다.
- 버튼을 누를 때도 목록을 다시 읽어 초기 이벤트가 없었던 환경을 처리한다.
- 목록이 아직 비었으면 `음성을 준비하지 못했어요. 잠시 후 다시 눌러 주세요.`라고 안내한다. 페이지나 학습을 로딩 상태로 막지 않는다.
- 나중에 목록이 준비돼도 자동으로 읽지 않는다. 사용자가 다시 눌러 재생한다.
- 비어 있지 않은 목록에 `en-US`가 없으면 음성 없음 상태로 표시한다. 목록 변경 시 다시 확인해 복구할 수 있다.

### 5.3 재생과 중단

- 재생은 사용자 버튼 조작 안에서 시작한다. 카드 공개·화면 복귀·음성 준비 완료로 자동 재생하지 않는다.
- 새 발음을 요청하면 앱의 기존 발음을 `cancel()`로 취소한 뒤 새 utterance를 생성해 `speak()`한다.
- 여러 번 눌러도 발음 요청이 대기열에 쌓이지 않는다.
- 다음 경우 즉시 취소하고 재생 표시·오류 상태를 정리한다.
  - 정답 제출 시작, 카드·Day·세션·라운드 변경.
  - 학습 완료 또는 오류 화면으로 전환.
  - 메뉴·전체 단어 목록 열기.
  - 페이지 숨김, 학습 컴포넌트 해제, 계정 변경·로그아웃.
- 취소 후에도 도착하는 이전 utterance의 `onstart`, `onend`, `onerror`는 현재 화면을 변경하지 못한다. 현재 재생 요청을 식별해 무시한다.
- `cancel()`로 발생하는 `canceled`·`interrupted`는 의도된 중단이면 사용자 오류로 표시하지 않는다.
- 컴포넌트 해제 시 이벤트 리스너와 utterance 참조를 정리한다. 개발 모드의 effect 재실행에도 구독이 중복되지 않는다.

### 5.4 기존 학습과의 관계

현재 타이머는 뜻 공개 시 중단된다. 발음은 그 이후에만 가능하므로 발음 기능이 타이머를 재시작하거나 시간을 늘리지 않는다.

발음 재생·완료·실패는 `submitResult`, 정답 개수, 응답 시간, 라운드 번호, 학습 세션 저장에 영향을 주지 않는다. 재생 도중에도 알았어요·몰랐어요 버튼을 누를 수 있고, 누르면 발음을 중단한 뒤 기존 제출 절차로 진행한다.

## 6. 오류와 안내

| 상황 | 화면 안내 | 이후 동작 |
| --- | --- | --- |
| 음성 합성 API 미지원 | 이 기기에서는 발음 듣기를 지원하지 않아요. | 발음 버튼 비활성, 학습 계속 |
| 초기 음성 목록이 비어 있음 | 음성을 준비하지 못했어요. 잠시 후 다시 눌러 주세요. | 다시 누르면 목록 재조회, 자동 재생 없음 |
| 목록은 있으나 미국 영어 음성 없음 | 미국 영어 음성을 사용할 수 없어요. 기기의 음성 설정을 확인해 주세요. | 버튼 비활성, 목록 변경 시 재확인 |
| 재생할 단어가 비어 있음 | 재생할 단어가 없어요. | 재생하지 않고 학습 계속 |
| 재생 호출 예외·의도하지 않은 재생 오류 | 발음을 재생하지 못했어요. 다시 눌러 주세요. | 재생 상태 해제, 재시도 허용 |
| 의도된 취소·화면 이탈 | 없음 | 즉시 정리, 돌아와도 자동 재생 없음 |

단어·뜻·예문·전체 음성 목록을 새 로그에 기록하지 않는다. 진단 로그가 필요하면 기존 로깅 기능으로 오류 코드와 처리 단계만 기록한다. 음성 합성 오류 때문에 학습 화면 전체를 오류 페이지로 보내지 않는다.

일부 음성은 브라우저 또는 운영체제 공급자의 네트워크 서비스를 사용할 수 있다. 앱이 자체 외부 TTS API를 호출하지 않는다는 사실을 기기 내부 처리 또는 오프라인 보장으로 설명하지 않는다.

## 7. 구현 단위

1. 재생 로직: 지원 확인, 음성 선택, 재생·중단과 오래된 콜백 차단을 작은 프론트엔드 단위로 구현한다. 새 상태 관리·오디오 라이브러리는 추가하지 않는다.
2. 카드 결합: 현재 공개 상태를 이용해 버튼을 표시하고 카드·메뉴·정답 제출·언마운트 경로에 정리 동작을 연결한다.
3. 스타일·접근성: 기존 버튼 패턴을 재사용하고 카드의 상위 버튼 역할을 공개 상태에 맞춰 조정한다.
4. 테스트: 기존 Node/tsx 테스트 방식을 우선 사용하고 브라우저 API를 가짜 객체로 대체해 핵심 상태 전이를 검증한다. 실제 소리·상호작용은 브라우저에서 추가 검증한다.

예상 변경 파일은 `study-app.tsx`, `globals.css`, 작은 발음 로직 파일과 해당 테스트, `frontend/package.json`이다. 구체적 파일 분리는 구현 시 결정하며 테스트를 위해 범용 음성 프레임워크를 만들지 않는다.

## 8. 테스트 명세

### 8.1 자동 검증

| ID | 시나리오 | 통과 기준 |
| --- | --- | --- |
| SP-01 | 한글 기본 음성과 en-US 음성이 함께 존재 | en-US 음성을 명시적으로 선택하고 현재 단어만 전달 |
| SP-02 | en-US 없음 또는 API 없음 | 비영어 기본 음성으로 읽지 않으며 처리 중 예외가 화면으로 전파되지 않음 |
| SP-03 | 최초 빈 목록 → voiceschanged 또는 재조회로 목록 준비 | 음성이 준비되더라도 자동 재생하지 않고 다음 클릭 시 재생 |
| SP-04 | 재생 중 연속 클릭 | 기존 요청 취소 후 새 요청 1개만 유효, 대기열 누적 없음 |
| SP-05 | 이전 요청 취소 직후 새 요청의 재생 시작 | 이전 요청의 완료·오류 콜백이 새 상태를 덮어쓰지 않음 |
| SP-06 | speak 예외·onerror·정상 onend | 상태가 적절히 정리되고 실패 후 재시도 가능 |
| SP-07 | 취소·해제 | 이전 재생 정리, 의도된 취소를 오류로 안내하지 않음 |

표시 조건·키보드·카드 전환처럼 실제 UI 결합이 필요한 항목은 수동으로 검증한다. 이미 사용할 수 있는 UI 테스트 도구가 있다면 자동화하되 이번 기능을 위해 큰 테스트 도구를 도입하지 않는다.

### 8.3 실제 음성 품질

- Windows의 실제 사용 브라우저, 실제 사용 휴대폰 브라우저, 해당 휴대폰의 설치형 PWA에서 확인한다.
- 각 결과에 OS·브라우저 버전, 선택된 음성 이름·언어, 성공 여부와 관찰된 문제를 적는다. 브라우저에서 읽을 수 없는 음성 정보는 확인 불가로 표시한다.
- 표본: apple, world, thought, through, comfortable, environment, record, read 및 사용자가 업로드한 단어 일부.
- 정상 기준: 버튼 조작으로 단어가 들리고 한국어 음성으로 읽지 않으며 심한 끊김·중복 재생이 없다.
- record·read처럼 발음이 여러 개인 단어는 모든 의미별 발음을 보장하는 시험이 아니다. 출력 발음을 기록하고 현재 의미와 다르면 한계로 명시한다.
- 실제 사용 기기에서 발음이 학습용으로 부적절하면 완료 처리하지 않고 음성 방식 변경을 논의한다. 미보유 기기의 검증은 통과로 표기하지 않는다.

## 9. 개발 및 검증 순서

| 단계 | 작업 | 다음 단계 진입 기준 |
| --- | --- | --- |
| 1 | 이 명세 확인, 이슈 #1에서 범위 확정 | 표시 조건·미국 영어 선택·시간 초과 예외가 명확함 |
| 2 | 최신 main을 기준으로 `codex/1-word-pronunciation` 브랜치에서 구현 | 기존 변경을 보존하고 기능 코드·핵심 테스트 준비 |
| 3 | 자동 검사와 UI 회귀 검증 | 관련 테스트, frontend lint·typecheck·build 통과 |
| 4 | 실제 휴대폰과 PWA 음성 검증 | 실제 사용 환경의 재생과 발음 품질 확인 |
| 5 | 이슈 #1을 연결한 PR 작성 | 변경 이유·검증 결과·미검증 환경·한계 명시 |
| 6 | 최종 리뷰 및 사용자 확인 | 승인 후 병합, 이슈 완료 처리 |

프론트엔드 검사 명령은 다음과 같다. 새 테스트 파일은 `frontend/package.json`의 test 명령에 포함한다.

```powershell
npm --workspace frontend run test
npm --workspace frontend run lint
npm --workspace frontend run typecheck
npm --workspace frontend run build
```

테스트의 가짜 음성 호출 성공을 실제 소리가 나거나 정확한 발음이라는 증거로 사용하지 않는다. 기능의 기존 결함과 이번 변경으로 생긴 결함을 구분하고 결과에 기록한다.

## 10. 완료 정의와 검증 상태

다음 조건이 충족돼야 구현 완료로 판단한다.

- 구현이 위 표시·재생·중단·오류 규칙을 만족한다.
- 자동 검사와 화면 회귀 검증의 결과가 기록돼 있다.
- 실제 사용 휴대폰과 PWA에서 소리와 발음 품질이 확인됐다.
- 영어 음성이 없는 환경에서도 학습이 가능하다.
- PR에 이슈 #1 연결과 검증 근거가 있고 최종 리뷰가 끝났다.

구현 및 프론트엔드 테스트 11개와 프로덕션 빌드 검증을 완료했다. SP-01~07의 핵심 재생 로직은 가짜 브라우저 API를 이용한 4개 테스트로 검증했다. UI-01~10의 실제 브라우저 상호작용, 휴대폰·PWA 청취와 최종 리뷰·병합은 아직 수행하지 않았다. 이 문서는 개발 일지가 아닌 기능 요구사항·검증 명세다.
